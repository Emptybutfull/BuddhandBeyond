## 1. What is the full "/3d-jutsu" recipe: what does the scene builder do, what is Blender's role, what can the agent script with Python, what are the outputs, and what does each step cost?

### Takeaway
"3D Jutsu" is a hosted, revision-controlled Blender 5.2 scene that the agent builds and edits entirely by sending Python (`bpy`) through the `scene_builder_3d_*` tools; nothing is installed on the user's computer and building, editing and rendering are stated to cost no credits. Credits are spent only when a render is turned into an AI image (`scene_builder_3d_generate_angles`, quoted at 2.5 credits per 2K image) or an AI video (`scene_builder_3d_generate_video`, Seedance 2.5, quoted at 15 / 35 / 80 credits for 5 s at 480p / 720p / 1080p); outputs are PNG/JPEG/MP4 renders, a downloadable `.blend`, a downloadable `.glb`, an interactive 3D preview, and those paid AI images/videos.

### Cited Findings

#### What it is and when the connector says to use it
- "3D Jutsu is a hosted, revision-controlled 3D scene. You build and edit it by running Python (`bpy`) through the `scene_builder_3d_*` tools; nothing is installed on the user's computer." Use is described as "3D scene, room, set, prop layout, camera, lighting or animation work in a 3D Jutsu project." — [PI:/3d-jutsu]
- The server instructions tell the agent: "For 3D scenes or location angles outside Blender Studio, first call get_preset_instructions with { preset: "/3d-jutsu" }. Includes new camera views of the same supplied location; image critique alone is not scene work." — [SERVER]
- The agent is told to "Talk to the user about their scene, project, render and export, not about containers or the runner." — [PI:/3d-jutsu]

#### Step 0: pick one of three routes (the agent must ask once unless the user already chose)
- Route A, hosted scene (3D Jutsu): "free to build. Nothing to rent or install, and building, editing and rendering spend no credits; only an AI image or video made from a render does. The simple default." — [PI:/3d-jutsu]
- Route B, Blender Studio: "the prosumer option. A rented GPU box running full Blender that the user opens in the browser, for heavier or professional work, their own files and generated meshes. The GPU is billed in credits by the second for as long as the box runs." — [PI:/3d-jutsu]
- Route C, "The Blender on the user's own computer (`/scene-builder`): free, needs a one-time setup." — [PI:/3d-jutsu]
- The agent goes ahead without asking only if the user typed `/3d-jutsu`, asked for a hosted 3D Jutsu scene, is continuing a 3D Jutsu project, named Blender Studio, or selected `/scene-builder`/local Blender. "In every other case ask once which route they want, before anything else. This covers a 3D scene with no route named, new views of a supplied location, and "in Blender" without saying which Blender." It must "Say which is free and which costs credits every time you offer them", and "The answer holds for the rest of the conversation". — [PI:/3d-jutsu]
- Two cross-route rules: (1) "One standalone 3D model of an object from an image, with no scene around it, is not a scene: use image-to-3D generation." (2) For one specific subject from a reference image inside a scene, the agent asks once "whether to generate it from the image (costs credits, close likeness, harder to edit) or model it from simple shapes (no generation cost, simpler, editable)." — [PI:/3d-jutsu]
- Hard limit of the hosted route: "This version imports catalog assets only, so a generated or uploaded mesh cannot enter a hosted scene: say so, and offer a catalog asset, a build from simple shapes here, or Blender Studio. Never wrap a picture around a mesh as its texture in place of modelling and materials." — [PI:/3d-jutsu]; the `generate_3d` tool repeats: "Hosted 3D Jutsu cannot import the result." — [SCHEMA:generate_3d]

#### The work loop (exact order)
- Every project-scoped tool takes an explicit `projectId`. Existing scene: `scene_builder_3d_list_projects`; new scene: `scene_builder_3d_create_project` once (not idempotent; "another create can make a duplicate"). "An authorized project with `exists: false` is a valid empty scene at revision 0, not an error." — [PI:/3d-jutsu], [SCHEMA:scene_builder_3d_create_project]
- "Two numbers guard every write: `revision` (the committed version) and `sceneSequence` (the settled scene state your code was written against)." Loop: 1) `scene_builder_3d_get_project`; 2) `scene_builder_3d_query_python` to inspect ("Queries commit nothing; use them freely. Never guess a name, unit or API."); 3) pick a stable `operationId` (idempotency key); 4) `scene_builder_3d_run_python` with the query's `revisionBefore` as `revision` and `sceneSequenceAfter` as `expectedSceneSequence`; 5) one mutation at a time per project, poll `scene_builder_3d_get_operation` (terminal statuses: `succeeded`, `failed`, `timed_out`, `expired`); 6) on success `revisionAfter` is the new head; 7) on a stale-state conflict re-query and regenerate the edit. — [PI:/3d-jutsu]
- Error handling: Python exception → fix the code; `EXECUTION_TIMEOUT` → "nothing was committed. Retry only with cheaper or split work"; `CONTAINER_UNAVAILABLE` → resubmit the same code under a new operation ID. — [PI:/3d-jutsu]
- Every finished creation/edit/import ends with `scene_builder_3d_show_scene` once, with the exact final revision: "This shows the result to the user; a text summary or download link alone does not finish scene delivery." — [SCHEMA:scene_builder_3d_run_python]

#### Blender's role, the runtime and its stated limits
- "This worker pins Blender 5.2: use `BLENDER_EEVEE`, `BLENDER_WORKBENCH`, or `CYCLES`, not `BLENDER_EEVEE_NEXT`." — [SCHEMA:scene_builder_3d_run_python]; "`bpy` API 5.2, headless." — [PI:/3d-jutsu]
- "Execution has a service-configured deadline (currently about five minutes per operation) and code is capped at 256 KiB. Renders are the expensive part: keep resolution and samples small and split large builds into coherent mutations." — [PI:/3d-jutsu]
- "The runtime has no network access. Do not fetch URLs, read files from elsewhere, or embed model or image bytes in Python." — [PI:/3d-jutsu]
- No external images at all: "even a DNS lookup hangs until the execution deadline kills the operation. There is currently no path to bring an external image into the scene. So today: materials are procedural (Principled BSDF values, noise/voronoi/wave textures, colour ramps, node groups)." A generated texture "is for _you_ to look at ... and translate into procedural values and geometry, not for the scene to load. Say this plainly to a user who asks for a generated texture on a model". A missing image texture renders "flat magenta and that is a failure, not a material." — [PI:/3d-jutsu/references/lookdev-lighting]
- "Each operation starts from the settled scene, not from your previous operation's selection." Removed APIs that raise are listed (`SceneEEVEE.use_bloom`, `Mesh.use_auto_smooth`, `RenderSettings.tile_x/tile_y`, pre-AgX looks). — [PI:/3d-jutsu]
- Light types: "Use Sun, Spot or Point lights: the scene view and GLB export drop Area lights." — [PI:/3d-jutsu]

#### What the agent can script with Python
- Inspection: "exact names, metre-scale dimensions, transforms, parents, collections, materials, cameras, lights, visibility, and animation settings", plus Blender RNA when an API or enum is uncertain; "Temporary scene changes are discarded, including camera changes used for inspection." — [SCHEMA:scene_builder_3d_query_python]
- Building: geometry, modifiers, materials, cameras, lights, world, keyframes and constraints. The references cover whole-scene blockouts, hard-surface modelling (lofted cross-sections, cut recesses, three detail levels, bevels), instancing ("build one mesh datablock with `bpy.data.meshes.new` and link many objects to it"), procedural materials and wear, a Nishita Sky Texture world, AgX view transform, product lighting with emissive cards, night scenes and fog, turntables, camera orbits, idle motion, constraints and loops. — [PI:/3d-jutsu/references/scene-building], [PI:/3d-jutsu/references/composition-modeling], [PI:/3d-jutsu/references/lookdev-lighting], [PI:/3d-jutsu/references/animation-audit]
- Rendering and publishing: "`artifacts` is the only way a file leaves an operation"; "At most eight `image/png`, `image/jpeg` or `video/mp4` files per operation." Schema limits: "512 MiB each and 1 GiB total; images at most 16384 pixels per side and 64 MP." A query (non-committing) can also render and publish a preview. — [PI:/3d-jutsu], [SCHEMA:scene_builder_3d_run_python], [SCHEMA:scene_builder_3d_query_python]
- Recommended build order ("Build a scene, not a script"): decide deliverable, hero/mid/background roles, camera and light motivation; name objects by role (`HERO_robot`, `ENV_floor`, `CAM_main`, `LGT_key`); first mutation places the delivery camera and a working light rig; then gates in order: silhouette, proportion, depth, contact, camera read, detail. "A succeeded mutation proves the code ran, not that the scene is right. Render from the delivery camera, retrieve the artifact, look at it, fix the largest visible defect and re-render before calling the work done." — [PI:/3d-jutsu]
- Render budget guidance: "one render per operation, `BLENDER_WORKBENCH` for pure-form checks (it ignores scene lights), `BLENDER_EEVEE` at modest resolution and low samples whenever the light has to be judged ..., `CYCLES` only when the user asked for it and the scene is small enough to finish. A render that times out is not evidence either way." — [PI:/3d-jutsu/references/scene-building]
- Animation limits: "Keyframes are cheap; rendering them is not." "An MP4 is a stretch goal, not the default. Attempt one only when the user explicitly wants video, after the stills pass, with a tiny frame range, low resolution and `BLENDER_WORKBENCH` or low-sample `BLENDER_EEVEE`. If it times out, say so and deliver the stills plus the `.blend` ... so the user can render locally". "The `.blend` export carries the animation intact." Simulation bakes are discouraged: "a simulation bake is execution time you do not have; prefer keyed motion." — [PI:/3d-jutsu/references/animation-audit]

#### Bringing models in
- "Models enter only through `scene_builder_3d_search_assets` then `scene_builder_3d_import_asset` ... This version imports curated catalog assets only; it cannot import a user's own file. Each import is one tracked object." — [PI:/3d-jutsu]
- Import transform uses "Editor/glTF coordinates: metres, Y up, XYZW quaternion. Blender bpy coordinates are Z up". — [SCHEMA:scene_builder_3d_import_asset]

#### Outputs
- Renders (PNG/JPEG stills, small MP4) retrieved with `scene_builder_3d_get_artifact` as a "short-lived download". — [SCHEMA:scene_builder_3d_get_artifact]
- `.blend`: `scene_builder_3d_get_blend` gives "a short-lived download for the current committed editable Blender file, or a specified historical revision." — [SCHEMA:scene_builder_3d_get_blend]
- `.glb`: `scene_builder_3d_get_glb` gives the current committed GLB or a historical revision; "Procedural shading, world lighting, and some Blender features may differ in GLB. A successful download does not establish that the exported scene looks correct." — [SCHEMA:scene_builder_3d_get_glb]; "Procedural shader graphs do not generally survive glTF. Use glTF-compatible material inputs (Principled BSDF with plain values or image textures) or bake the appearance that must travel." — [PI:/3d-jutsu/references/composition-modeling]
- Interactive preview for the user: `scene_builder_3d_show_scene` ("The widget is for the user to inspect; it does not give the agent visual evidence"; falls back to a `projectUrl`). — [SCHEMA:scene_builder_3d_show_scene]
- AI image from a render: `scene_builder_3d_generate_angles` "using 3d_jutsu_angles (Seedream V5 Pro pricing). This spends credits." Needs the `operationId`/`artifactId` of an inspected PNG/JPEG render; optional one `referenceMediaId` (an uploaded photo or first video frame); aspect ratios 1:1, 4:3, 3:4, 16:9, 9:16, 3:2, 2:3, 21:9; resolution 1k / 1.5k / 2k (default 2k); "The scene itself is unchanged." — [SCHEMA:scene_builder_3d_generate_angles]
- AI video from a render: `scene_builder_3d_generate_video` is "a paid Seedance 2.5 video"; modes t2v, omni_reference, video_edit, video_extension; "Supports up to 30 images, 10 videos, 10 audio clips, 50 total"; a published Blender render can be the `start_image`; duration 4 to 30 s (default 5); resolution 480p / 720p / 1080p (default 720p); aspect auto, 21:9, 16:9, 4:3, 1:1, 3:4, 9:16; `generateAudio` default true; `draft` (480p) and `draftJobId` (1080p finalization). — [SCHEMA:scene_builder_3d_generate_video]
- Important distinction: "A rendered MP4 shows the authored animation. A Seedance video from `scene_builder_3d_generate_video` is a paid AI generation from one render, not a render of the keyed motion; use it only when the user asks for AI video." — [PI:/3d-jutsu/references/animation-audit]
- Paid calls are idempotent by `requestId`: "Never submit another paid generation or allocate a new requestId to recover it." — [SCHEMA:scene_builder_3d_get_generation]

#### Costs per step
- Create project, query, run Python, import catalog asset, render, download `.blend`/`.glb`, show scene: "A hosted scene is free to build: nothing to rent, and building, editing and rendering spend no credits (only an AI image or video from a render does)." — [SCHEMA:scene_builder_3d_create_project]
- `3d_jutsu_angles` image, 2k, 16:9: quoted 2.5 credits. — [EST:image model=3d_jutsu_angles resolution=2k]. The catalogue describes it as "3D Jutsu Angles powered by Seedream 5.0 Pro". — [ME:search "seedream"]
- Seedance 2.5 video, 5 s, 16:9, no media attached: 15 credits at 480p, 35 at 720p, 80 at 1080p (3 / 7 / 16 credits per second). — [EST:video model=seedance_2_5]. These quotes were made against the generic `seedance_2_5` model, not through the scene-builder tool itself.

#### "New views of a supplied location" sub-recipe
- Loaded before construction via `/3d-jutsu/references/location-new-angles`. Sequence: inspect the source image; ask only about unresolved hidden areas (especially behind the source camera); offer "a reverse wide, optional side medium and optional detail"; build the visible location under a saved source-control camera with simple colours ("spend geometry on identity and spatial relations"); verify with a small material-colour preview plus a top view; compose new cameras; render clean angle references "at the source's actual aspect ratio"; write a per-view prompt; quote; then generate. — [PI:/3d-jutsu/references/location-new-angles]
- Paid-step gate: "finish geometry, camera checks, clean previews, reference preparation, per-view prompts and a current cost estimate before requesting approval ... A general request for new angles alone is not approval of that paid batch." "Start with one image per selected view." "Allow at most one targeted generation retry per failing angle within authorized spending." — [PI:/3d-jutsu/references/location-new-angles]
- Default references per generated view: two (the user's master image for identity/materials/lighting, the current 3D angle render for camera/layout). The hosted path "supports one optional uploaded reference and enumerated `aspectRatio`, not arbitrary extra images or width/height." — [PI:/3d-jutsu/references/location-new-angles]
- The same reference warns: "Do not hardcode historical prices or claim scene work is free." and "One image does not establish exact metric dimensions or hidden geometry." — [PI:/3d-jutsu/references/location-new-angles]

#### The other two Blender routes, as the connector describes them
- Blender Studio (`/gpu`): rent with `gpu_rent kind: blender_studio` after showing GPU, count and hourly rate and getting "my explicit yes"; "The box bills by the second from when it is ready (no minimum) until `gpu_rental_stop` is called, my credits run out, or it sits idle for `auto_pause_minutes` (default 10 ...)". Scripts run with `gpu_rental_exec` (each call a fresh shell, max 90 s); `/workspace` persists across boxes, everything else is wiped. In Blender Studio the default is to "build what I ask for directly in Blender with Python"; a generated mesh GLB can be imported there, and a picture can be loaded as a reference image. Not offered in Belarus, China (incl. Hong Kong), Cuba, Iran, Macau, North Korea, Russia or Venezuela. Render advice: "a still or a short test renders fine on one L40S"; "Before a long render, render one test frame and tell me its time". — [PI:/gpu]
- Blender presets that run locally or on a Blender Studio box: `/destruction-studio` (building-collapse simulations, skill `blender-destruction`), `/exploded-view` (assembly/breakdown animations, skill `blender-camera-led-assembly`), `/scene-builder` (camera blocking, rooms, character staging, skill `blender-camera-blocking`), `/cartoon-shaders` (stylized materials, skill `blender-stylized-materials`). On a box the skill is downloaded from the public npm package `fnf-blender-mcp`, the scene lives at `/project/scene.blend`, and scripts run with `blenderctl run FILE`. Each preset offers hosted 3D Jutsu as a fallback, noting it "builds a separate hosted scene and cannot open the user's local `.blend` files". — [PI:/gpu/references/blender-presets], [PI:/scene-builder], [PI:/exploded-view], [PI:/destruction-studio], [PI:/cartoon-shaders]
- Local Blender (`/use-blender`): "Desktop client → stdio → fnf-blender-mcp → process pipes → Blender Python / bpy", "No add-on, HTTP listener, WebSocket or cloud account is required". It needs a shell on the same computer as Blender: "Claude Desktop Chat and Cowork are not supported for this host installation flow. Code Cloud and Higgsfield `sandbox_exec` are not host shells either." It "cannot read unsaved work in an already-open Blender window". — [PI:/use-blender]
- The `/gpu` help text positions the apps: Blender for "modelling, sculpting, lookdev and lighting, character animation, motion graphics, and most stills and animations; renders with Cycles (path traced) or Eevee (fast)". — [PI:/gpu]

### Inferences
- For a non-expert in chat, the practical order for a hosted scene is: choose route → create project (free) → agent blocks out and lights the scene in Python (free) → agent renders small previews and inspects them (free) → user looks at the interactive preview → optional `.blend`/`.glb` download (free) → optional paid AI image per view (about 2.5 credits each at 2K) and/or paid Seedance 2.5 video from a render (35 credits per 5 s at 720p on today's quote).
- The hosted scene is best understood as a blockout/layout and camera tool whose photoreal look comes from the paid AI image/video step, because the runtime cannot load image textures, HDRIs, user meshes or generated meshes and has a roughly five-minute per-operation limit.
- Anything needing the user's own `.blend`, generated meshes, image textures, simulations or long Cycles animation renders points to Blender Studio (paid by the second) or local Blender (free, but needs a local Claude Code or Codex session, which this cloud session is not).
- Location-new-angles cost for the default three offered views is about 7.5 credits at 2K plus up to one retry per failing view, if the 2.5-credit quote holds.

## 4. Are there slash recipes for motion graphics, logo stings, kinetic typography or transitions, and what else exists in the preset galleries?

### Takeaway
There is no "vibe motion", "motion-craft" or "motion-graphics" recipe: those tokens fall through to a generic "use ordinary generation" instruction. What does exist is (a) Higgsedit in the cloud sandbox for authored motion graphics, (b) a family of After Effects commands, including `/logo-animation` and `/kinetic-typography`, that require After Effects on the user's own computer (some also run in "EffectCraft" on a rented Artcraft box), (c) the reel-effects commands, (d) a 231-item Marketing Studio "Motion" preset gallery of generative motion styles, and (e) one Marketplace app, "Match Cut + Tracelab", with word-reel, logo-cut and typewriter modes.

## 5. What does the connector say about the cloud sandbox (tools, limits, charging), about review loops (inspecting frames, video analysis), and is there a tool that lets the agent "watch" a video, at what cost?

### Takeaway
The sandbox is a per-user remote Linux box with ffmpeg, ImageMagick, sox, Python, Node and headless Chromium preinstalled; using it is stated to cost 0 credits, with 60 to 120 second foreground calls, 15-minute background jobs and a way to return up to four small images to the agent for real visual inspection. Two paid tools "watch" a video: `video_analysis_create` (scene-by-scene storyboard or a question answered about the video, 3 to 5 minutes, historically observed at about 2.2 to 2.3 credits per call) and `virality_predictor` (engagement dashboard, cost not stated); the free alternative used by every workflow is contact sheets viewed through `image_paths`.

### Cited Findings

#### Sandbox
- What it is: "a remote Higgsfield cloud Linux sandbox — NOT your local machine or the client's own shell." "Do not use it to inspect a local repository, install desktop software, or control applications on the user's computer." — [SCHEMA:sandbox_exec]
- Preinstalled: "ffmpeg/ffprobe, ImageMagick, sox, python3 with Pillow and faster-whisper, node/npm/npx, sharp-cli, Playwright with headless Chromium, caption fonts (Metropolis, Montserrat), zip/unzip, git, curl, jq." — [SCHEMA:sandbox_exec]. A Katana reference adds: Debian, Python 3.11, numpy, onnxruntime, ffmpeg 5.1, node 20; "It has no cv2, scipy, librosa, soundfile, torch, vidstab, `bc` or `/usr/bin/time`"; `yt-dlp` is preinstalled; fonts "Montserrat, Metropolis, DejaVu, Liberation, Noto Color Emoji and CJK fonts", with Montserrat and Metropolis "only in the ExtraBold weight". — [BF:katana/references/sandbox.md]
- Charging: "A `sandbox_exec` call costs 0 credits." — [BF:katana/references/sandbox.md]; `sandbox_exec`, `media_upload`, `media_confirm`, `media_import_url`, `jobs_wait` are in the "free" list. — [BF:katana/scripts/prices.json]. The tool description itself states no price.
- Limits: commands "time out after timeout_seconds (default 60, max 120)"; "Background commands have a 15-minute execution limit"; command length limit 128,000 characters; `size:"xl"` "only for the heaviest CPU work, such as a final multi-job video render" and the XL sandbox "shuts down about a minute after its work finishes". — [SCHEMA:sandbox_exec]
- Capacity and sharing: "There is one sandbox per account, shared by every chat of that user (8 vCPU, ~7 GB RAM, ~21 GB disk). A foreground call that hits its timeout, or a `restart: true`, wipes it for everyone, including other chats' background jobs." Practical advice: keep foreground calls under about 45 s; a foreground call that waited about 100 s failed with "server isn't responding". — [BF:katana/references/sandbox.md]
- Persistence: "Workspace files in /home/user persist across idle replacement for 24 hours since last use. Processes and RAM do not survive replacement. Files outside /home/user are checkpointed best-effort; export finished results." — [SCHEMA:sandbox_exec]; contradicted by "Files are discarded ~10 s after a call finishes. Back-to-back calls see the same files." — [BF:katana/references/sandbox.md] (dated "VERIFIED live 2026-10-08"), and by workflows that say "The sandbox is ephemeral: chain each stage in one command." — [WF:lighting-hf]
- Network and file transfer: "It has internet access: bring files in with curl from confirmed uploads or generation result URLs." Outputs leave by calling `media_upload` first, then a `curl -f -X PUT ... --upload-file` in the same command, then `media_confirm` after HTTP 200. "Client attachment upload tools cannot read sandbox paths". — [SCHEMA:sandbox_exec]
- No GPU: GPU work "runs on a GPU box rented from Higgsfield, never ... in `sandbox_exec` (it has no GPU)." — [PI:/gpu]
- Bundled workflow scripts are preinstalled "in every sandbox under $HF_WORKFLOWS (/home/user/.higgsfield/workflows)"; the agent must "never paste script contents into the command." — [SCHEMA:sandbox_exec]
- Recovery: "If a Modal sandbox remains unresponsive, ask the user before using sandbox_id from its result as recover_sandbox_id: recovery stops all running work, retains /home/user". — [SCHEMA:sandbox_exec]

#### Review loops
- Native image return: "For actual visual inspection, pass image_paths (up to 4 PNG/JPEG paths, <=512 KiB total) with a foreground command: images are returned natively to the model, not as text or URLs." "Inspect the actual images before writing visual review verdicts." — [SCHEMA:sandbox_exec]
- How workflows use it: angles-hf views frame sheets "a frame every 0.25 s ... 20 frames to a sheet", two sheets per call, and says "Never judge a result from a few frames you pick yourself"; reel-effects checks stills "at a moment's start, peak and end, not one frame"; enhance-video shrinks contact sheets to fit the 512 KiB limit and also produces an SSIM report, a five-moment grid and a compare video; layer-reveal stacks the layers side by side with ffmpeg `hstack`. — [WF:angles-hf], [WF:reel-effects], [WF:higgsfield-enhance-video], [WF:layer-reveal-hf]
- 3D scenes use a separate loop: render with `scene_builder_3d_query_python`, fetch with `scene_builder_3d_get_artifact`, "Inspect the returned image using the client's image capability ... If the client cannot inspect it, describe that limitation rather than claiming a visual check passed." — [SCHEMA:scene_builder_3d_get_artifact]
- Higgsedit's own evidence commands: "`frame` / `render`: actual pixels and runtime diagnostics. `sheet` samples frames"; "`inspect --at`: evaluated parameters and lifetimes, not shader execution/world geometry." — [BF:video-editing/references/failure-modes.md]
- Audio is measured rather than heard unless a listening tool exists: "Listen when a tool supports actual listening; otherwise distinguish audio measurements from listening." — [WF:katana]

#### Tools that analyse or "watch" a video
- `video_analysis_create`: "Start a scene-by-scene analysis of a video. Provide EXACTLY ONE of: (a) video_input_id ... or (b) youtube_url — a YouTube link (youtube.com / youtu.be hosts only). Optionally pass prompt to ask a question about the video instead (answered in result.analysis), and mode='glance' for a faster, cheaper pass. Each analysis costs credits; if the user lacks them, the call fails with an upgrade link. ... Processing typically takes 3-5 minutes on average. IMPORTANT: warn the user up front that the longer the video, the less accurate the scene-by-scene analysis becomes". Modes: `deep` (default) and `glance`; prompt up to 4,000 characters. — [SCHEMA:video_analysis_create]
- `video_analysis_status`: poll "every 30-60 seconds" until `completed` or `failed`; `video_analysis_jobs` lists past analyses. — [SCHEMA:video_analysis_status], [SCHEMA:video_analysis_jobs]
- Observed cost: the analysis "is paid (~2.2–2.3 cr per call observed, FROM-EVIDENCE)", and Katana "never buys it ... its own sandbox analysis is free and frame-exact." — [BF:katana/references/mcp-api.md]
- `virality_predictor`: "predicts a video's virality potential, engagement, attention, audience response, retention risk, hook strength, and creative performance with an interactive dashboard." Input is a confirmed uploaded video or a completed generated video job; `preview` re-opens an existing dashboard. No price is stated in the tool. — [SCHEMA:virality_predictor]
- Sandbox speech-to-text is available without a paid model: `faster-whisper` is preinstalled, and angles-hf's `sheets.py` prints "`speech` (what is said in the clip, with times)". — [SCHEMA:sandbox_exec], [WF:angles-hf]
- Routing rule for analysis-only requests: video-editing must not activate "when the user only asks to analyze, summarize, describe, critique or review a video or YouTube link", and for Katana "Analysis requests authorize inspection only." — [WF:video-editing], [WF:katana]

### Inferences
- The agent can genuinely look at stills (up to four per call, small JPEGs) and read transcripts, but it does not watch moving video or hear audio directly; "watching" is either dense contact sheets (free, many calls) or the paid server-side analysis (minutes, a few credits, less reliable on long videos).
- The persistence statements conflict; the safe reading for planning is the tool description (24 hours for `/home/user`) with the workflows' defensive habit of chaining each stage in one command and uploading results immediately.
- Because there is one shared sandbox per account with about 7 GB RAM and a 15-minute background limit, long or high-resolution Higgsedit or Chromium renders may need splitting or the `xl` size; no render-time figures are given beyond "under a minute for 10 seconds" for the layer-reveal script.

### Gaps
- No current, tool-stated price for `video_analysis_create` (deep versus glance) or `virality_predictor`; the only figure is a historical observation in a Katana reference, and the model catalogue has no entry for either.
- XL sandbox specifications and whether XL use is also free are not stated.
- Sandbox facts in the Katana reference are dated 2026-10-08 and may be out of date relative to the tool description.
- The sandbox was not exercised (excluded), so installed versions, Higgsedit presence and actual persistence were not verified.
- Account balance and plan were not read, so no statement can be made about how far the user's credits go.
